# finder

The purpose of this project is to search [dba.dk](https://www.dba.dk/) and find things i might be interested in and inform me about them.

Practicaly its a automated python script which runs as a cron-job as a Github Action. It fetches results from my search, filters only the results which actually contain the search string in their title and store their links. Afterwards it opens all of those links and stores the body of the ad. This all information is afterwards concatanated and outputed from the python script. The output is later sent through a LLM with a custom filter which analyzes the optional ads and pick up only those which fit the filter. This text is later sent to my mailaddress using another python script.

The two python scripts are short, simple, follow [google python styleguide](https://google.github.io/styleguide/pyguide.html), they are uv scripts which have defined dependencies at the top of the file. They use the most default logger configuration and output progress in "- DBA Ad {add name} scraped" format. If something is wrong they throw an exception and let it bubble up. Each function has short, ideally one line long docstring describing purpose of the function. The function signatures contain types. The code is linted and formated using [ruff](https://docs.astral.sh/ruff/).

The github action pipeline is also very short and simple, it installs the python and executes the scripts. The script which sends mail receives credentials and addresses in env vars. It authenticates itself and sends the mail with a very basic formatting saying hello, potentialy interesting results and list where i can click a url to dba and a short description of the item from the LLM output. The script which scrapes dba does not receive any env vars. The call towards LLM is done directly in the github action, by calling a curl command which sources body from some file in this directory. This file contains the filter prompt. This step is authenticated using env var, or secret. It will be towards gemini api.
